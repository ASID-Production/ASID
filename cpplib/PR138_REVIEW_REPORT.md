## 3. Пропущенные или уточнённые предложения

- `n_knots` в актуальном ED.txt/конструкторе означает число интервалов, не число узлов. Поэтому 1 интервал (2 узла) корректен; механическое отклонение `n_knots<2` было бы ошибкой. Ноль интервалов отклоняется.
- Logarithmic constructor требует r_min>0; нулевой узел поддержан отдельным конструктором фактических узлов с гладким радиальным граничным условием.
- Не введён произвольный RADIAL_EPSILON: положительные радиусы вычисляются через hypot и единичный вектор, r=0 обрабатывается отдельно. Это не смешивает радиальную точность с Voronoi epsilon и не создаёт искусственную сферу постоянной плотности.
- Для ядерного cusp с ненулевой радиальной производной декартов Hessian в центре математически не существует. Вместо выдуманного нулевого Hessian возвращается domain_error. Для гладкого центра используется phi''(0) I.
- Небезопасные `-fno-signed-zeros`/`-fno-trapping-math` не добавлялись: задача требует сохранения FP-семантики.
- Заголовок PR и состояния обсуждений на GitHub не изменялись. Предложенный заголовок: `[cpplib/feature]: Analyze Bader critical points in proatomic electron density`.
- В HTML доступны исторические отметки Resolved/Outdated и актуальные обсуждения последнего ревью. Полная авторитетная выгрузка review-thread metadata не получена: публичный GitHub API вернул HTTP 403 rate limit. Поэтому полный перечень resolved/unresolved не объявляется подтверждённым.

## 4. Дополнительные обнаруженные проблемы

- Внутренние Python handlers находились в extern C. MSVC `/EHsc` считал вызовы не бросающими исключений, что приводило к аварийному завершению вместо RuntimeError. C linkage оставлен только у PyInit_cpplib. Ошибка воспроизведена тестами отсутствующих данных и устранена.
- Debug Python headers автоматически выбирали python310_d.lib вопреки Stable ABI. Debug C++ extension теперь работает с выбранным release Python через python3.lib; C++ assertions сохраняются.
- CTest multi-config запускал тесты из каталога без скопированных данных. Указан `$<TARGET_FILE_DIR:MyTests>`.
- Python module path в UTF-8 интерпретировался как Windows ANSI. Используется u8path; relocation tests проходят с кириллицей.
- Поиск значения сплайна мог читать узел за границей или пропускать последний интервал. Хранятся все m+1 узлов и конечное значение; корень ищется в фактическом bracket.
- Правая граничная система сплайна ошибочно предполагала нулевое конечное значение. Исправлено уравнение нулевой правой производной для произвольного конечного значения.
- DensityParser принимал неправильный заголовок, повторные элементы и недопустимые числовые токены. Добавлены проверки и проверка полного чтения файла. Разреженный список элементов ED.txt допускается.
- Отсутствующая плотность конкретного элемента проверяется до индексирования, остановка gradient path при нулевом градиенте не делит на ноль.
- Обнаружено некорректное отслеживание заголовков Ninja с локализованным MSVC. Итоговые результаты получены из чистых сборок генератором Visual Studio, а не из этих промежуточных Ninja-объектов.

## 7. Остаточные риски

- Для полного зелёного Release/ASan CTest требуется настоящий d10k.datt. Старый тест также использует путь, зависящий от расположения сборки.
- Linux/macOS, UBSan и полный предметный корпус сложных кристаллов не проверены.
- Тесты охватывают ранний RFO exit и сходимость, но отдельный сценарий достижения всех 64 RFO iterations с последующей несходимостью Newton не инструментирован.
- Частый diagnostic reload увеличивает память: старые поколения намеренно сохраняются, поскольку API выдаёт сырые ссылки и безопасный момент освобождения неизвестен.
- Продолжение первого полинома ниже r_min — явно выбранная экстраполяция существующей spline-модели, а не независимая реконструкция истинной ядерной плотности. Поведение cusp оговорено выше.
- Сохранились существующие compiler warnings о deprecated SpatialGrid и сужениях индексов в несвязанных участках. Новые замечания не устранялись массовым рефакторингом.
- Полная metadata-проверка всех скрытых GitHub discussions ограничена API rate limit.
